# Hypothesis gate

Use when a causal explanation will determine a change and a material alternative remains. This is a decision check, not a new permission boundary.

## Minimum useful record

- **Observation:** Report or measurement, source, time window, scope, and relevant revision.
- **Current best model:** Leading explanation, confidence and limits; "unresolved" is valid.
- **Material rival:** A plausible mechanism implying a different action, if one exists.
- **Falsifier:** A feasible result that lowers the leading model's rank or narrows its scope.
- **Discriminating evidence:** What the models predict differently and where to obtain it.
- **Decision:** Act, measure, mitigate, or wait for a named input; include budget and reopening condition.

"Check logs" is incomplete if it cannot change the decision. A test predicting the same outcome under every model is not discriminating. No minimum hypothesis count is required.

For saturation, compare capacity shortage against increased service/hold time. Busy resources fit both. Measure representative requests with consistent timing boundaries before selecting a capacity change.

## Outcomes

**Enough evidence:** Execute the justified change and relevant validation. Do not keep collecting evidence to finish a form.

**Missing evidence:** Use existing measurements first, then a bounded probe with outcome-to-update rules. Safe mitigation can be justified without the final cause; label it as mitigation and monitor it.

**Contradiction:** Revise the explanation before expanding the patch. Check [staleness](model-staleness.md) if the premise came from history.

**Inaccessible evidence:** State the exact gap and do independent authorized work. Do not report planned measurements as observed or invent causality to meet a deadline.

Close with an action, not a perpetual list of causes. See [decision cost](decision-cost.md).
